# Pembaruan VitaeManager — 25 Oktober 2026

Pembaruan dikerjakan langsung pada source project IntelliJ ini. Target tetap Paper **1.21.4**, Java **21**, namespace dan command lama dipertahankan. Wrapper aktual adalah Gradle **9.7.0**. Pada analisis update awal `rules.md` dan `AGENTS.md` belum ditemukan; pada pembaruan lanjutan `RULES.md` tersedia dan telah dibaca. `AGENTS.md` tetap tidak ditemukan; `PROJECT.md`, `ARCHITECTURE.md`, dan `VERIFICATION.md` yang ada dibaca, dengan catatan daftar modul dalam dokumen lama sudah tertinggal. Perubahan lokal `PANDUAN-SETUP.md` dipertahankan.

## Pemasangan dan data

1. Hentikan server secara normal. Backup folder world/playerdata dan folder data VitaeManager bersama.
2. Ganti JAR VitaeManager dengan hasil `gradlew.bat clean build` dalam `build/libs/`. Jangan memasang dua JAR VitaeManager bersamaan.
3. Pertahankan seluruh folder data plugin lama, termasuk `viti.yml`, backup, journal, dan receipt. Jangan menghapus atau membuat ulang konfigurasi untuk memasang versi ini.
4. Jalankan Paper 1.21.4 dengan Java 21. Periksa log migrasi, NPC, ekonomi, dan pemulihan domain sebelum membuka server untuk pemain.
5. Lakukan daftar pengujian server di bawah pada salinan server terlebih dahulu. JAR terkompilasi tidak membuktikan perilaku client atau crash server.

Plugin memakai `getDataFolder()` aktual (metadata `name: vitaemanager`), tanpa mengasumsikan folder bernama `VitaeManager`.

| Lokasi lama | Lokasi aktif setelah migrasi | Isi |
|---|---|---|
| `server-control.yml` | `server/state.yml` | Status kontrol server |
| `totem-settings.yml` | `totem/settings.yml` | Pengaturan batas totem |
| `whispers.yml` | `whisper/whispers.yml` | Definisi dan status bisikan dalam format lama |
| `evolution.yml` | `evolution/evolution.yml` | Konfigurasi, escrow, dan status evolusi dalam format lama |
| `npc.json` | `npc/npc.json` | NPC, quest, progres, dan pending reward |
| `dungeons.json` | `story/dungeons.json` | Dungeon dan pemulihannya |
| `fade.json` | `story/fade.json` | Pengaturan fade |
| `music.yml` | `music/music.yml` | Konfigurasi musik |

`config.yml`, `blocker/blocked.yml`, `viti.yml`, `viti.yml.before-remake`, marker/backup konversi mata uang yang lama, dan `viti-shop-spent.log` tetap di lokasi semula. Tidak ada perubahan kurs atau konversi saldo. File moneter sengaja tidak dipindahkan demi tampilan folder. Backup lama lain serta `fade-resourcepack/` juga dipertahankan.

Migrasi membuat backup byte asli di `migration/layout-backup/` sebelum menyalin. `migration/layout-journal/*.sha256` mencatat salinan yang disiapkan, `.complete` menandai verifikasi selesai. Sumber lama tetap disimpan sebagai arsip; sesudah selesai hanya lokasi baru yang digunakan. Edit konfigurasi di lokasi baru. Nilai default tidak ditulis menimpa konfigurasi pengguna. Format lama yang mencampur konfigurasi dan status tidak dipecah paksa.

Salinan terputus dapat diteruskan dari sumber yang hash-nya sama. Dua file bertentangan, backup berubah, file lama diedit setelah migrasi, atau tujuan aktif hilang setelah migrasi selesai menyebabkan startup ditolak dengan lokasi konflik di log. Tidak ada pemilihan diam-diam atau penggabungan progres. Admin harus membandingkan/menyelamatkan file yang dimaksud dari backup yang benar; jangan menghapus marker untuk memaksa pemuatan salinan lama.

File fitur baru:

- `npc/shops/catalogs.json`: katalog permanen berdasarkan token generasi NPC.
- `npc/shops/journal/<receipt>.json`: status transaksi serta snapshot inventory.
- `npc/shops/audit/<receipt>.json`: transaksi selesai; receipt dipertahankan.
- `magic/unlimited_misery.yml`, `magic/telekinesis.yml`, `magic/tunduk.yml`: satu konfigurasi per sihir.
- `magic/data/`: kepemilikan UUID, penggunaan, cooldown, dan catatan cleanup milik modul.
- `magic/recovery/domains/`: snapshot NBT, progres pemulihan, serta marker selesai domain.

## Carry dan ekonomi

Carry tidak menyisipkan nama pihak lain pada pesan mulai/diangkat/diturunkan. Mekanisme tanpa consent yang sudah ada dan permission `vitae.carry` tetap berlaku. Pesan bawaan lama yang persis cocok ditingkatkan di memori; konfigurasi pesan khusus admin tetap dipertahankan. Penggendong memakai `/carry` lagi untuk menurunkan.

`/viti`, `/uang`, `/money`, dan subcommand lama tetap tersedia. Tampilan saldo memakai `950`, `1k`, `1,5k`, `100k`, `1jt` dengan label Viti. Hover saldo menyediakan nominal lengkap; transaksi/harga tetap memakai nominal lengkap. `VitiAmount` tetap satu formatter bersama dan `BigDecimal` satu sumber aritmetika. Ringkasan dibatasi satu angka pecahan dan dipotong ke bawah untuk tampilan saja; nilai tersimpan tidak dibulatkan.

PlaceholderAPI opsional; tidak ada dependency TAB. Placeholder angka tanpa label:

| Placeholder | Contoh |
|---|---|
| `%vitae_viti%` | `12.500,75` |
| `%vitae_viti_raw%` | `12500.75` |
| `%vitae_viti_short%` | `12,5k` |
| `%vitae_viti_highest%` | Saldo tertinggi historis dengan format lengkap |

Permintaan hanya membaca snapshot immutable ledger dalam memori, termasuk permintaan asynchronous. UUID yang belum ada di ledger menghasilkan `0`; akun online diimpor oleh lifecycle ekonomi yang sudah ada. Identifier `vitae` tidak menimpa ekspansi lain; konflik pendaftaran dicatat di log. Ekspansi internal memakai `persist()` dan unregister saat plugin berhenti, mengikuti [dokumentasi PlaceholderAPI](https://wiki.placeholderapi.com/developers/creating-a-placeholderexpansion/).

Contoh teks TAB: `&fViti: &a%vitae_viti_short%`. Tambahkan secara manual pada bagian yang sesuai dalam konfigurasi TAB, gabungkan dengan pengaturan yang sudah ada:

```yaml
placeholder-refresh-intervals:
  "%vitae_viti%": 1000
  "%vitae_viti_raw%": 1000
  "%vitae_viti_short%": 1000
  "%vitae_viti_highest%": 1000
```

Interval TAB memakai milidetik; `1000` berarti sekitar satu detik. Periksa nama bagian pada versi TAB Anda. VitaeManager tidak mengubah konfigurasi TAB. Lihat [panduan resmi refresh TAB](https://github.com/NEZNAMY/TAB/wiki/Optimizing-the-plugin).

## Command dan integrasi

Semua pemain dapat `/sihir`; tidak ada `/sihir akses`. `/sihir info <id>` dan `/sihir pakai <id>` memeriksa kepemilikan. Command langsung dan tombol GUNAKAN memakai validasi aktivasi yang sama. GUI koleksi dan konfirmasi masing-masing sembilan slot; konfirmasi BATAL=2, informasi=4, GUNAKAN=6.

Permission admin baru: `vitae.sihir.admin` (default OP, turunan `vitae.admin`).

```text
/sihir beri <player> <id>
/sihir hapus <player> <id>
/sihir cek <player>
/sihir hentikan <player>
/sihir cooldown reset <player>
/sihir reload
```

ID awal: `unlimited_misery`, `telekinesis`, `tunduk`. Maksimal sembilan sihir berbeda per UUID, tanpa duplikat. Identitas offline harus sudah dikenal server; tidak membuat UUID tebakan. Cooldown bersama lima menit dimulai setelah penggunaan dan cleanup/pemulihan selesai, tersimpan sebagai waktu absolut. Reset cooldown tidak membuka penggunaan aktif.

Wajib untuk plugin: Paper 1.21.4 dan Java 21. Opsional untuk keseluruhan plugin, tetapi wajib untuk mekanik terkait: LuckPerms API 5.1+ untuk Unlimited Misery (grup diwariskan `antihero`, bukan wildcard/OP); Tunduk kini memakai pose native Paper dan tidak memerlukan GSit. Deklarasi integrasi GSit lama dipertahankan. Kompatibilitas LuckPerms runtime tetap perlu diuji langsung. Ketidaktersediaan API menolak aktivasi terkait dengan alasan jelas. Telekinesis tidak membutuhkan keduanya. PlaceholderAPI dikompilasi sebagai `compileOnly` 2.11.6 dan tidak dibundel. Integrasi lama tetap dipertahankan; MythicMobs, MMOItems, MythicLib, TAB, dan ItemsAdder tidak menjadi dependency wajib modul sihir.

Sound vanilla adalah default. Sound custom memakai ID resource pack yang sudah dimiliki client, termasuk pack ItemsAdder, tanpa dependency ItemsAdder untuk memutar ID tersebut. Konfigurasi sihir mengatur nama, deskripsi, ikon, radius, durasi yang didukung mekanik, partikel, sound per tahap, interval, volume/pitch, healing, dan debuff. Reload mempertahankan konfigurasi awal penggunaan yang masih aktif. Mekanik tambahan membutuhkan implementasi Java dan bukan YAML semata.

Detail parameter dan lifecycle sihir: [panduan modul sihir](MAGIC-MODULE.md).

Toko memakai `/vnpc <id> shop ...` dengan permission lama `vitae.admin.npc`; lihat [panduan toko](NPC-SHOPS.md). Empat template hanya berlaku pada katalog kosong dan harga memakai nominal Viti asli. Dua carrot dari harga 64=85 menghasilkan tepat `2,65625` Viti. Tidak menerbitkan uang kertas. Pemain membuka lewat NPC, bukan command jarak jauh. Admin jongkok+klik kanan mengedit; contoh disalin tanpa dikonsumsi.

## Batasan dan pengujian server

Lihat [pemulihan domain](DOMAIN-RECOVERY.md) untuk snapshot penuh, batas blok yang diterima, batch server-thread, verifikasi NBT, serta flush world sebelum penandaan selesai. Lokasi dengan struktur/physics yang belum aman ditolak; ini membatasi area praktis domain. Pengecualian mekanik sihir tidak mengubah flag WorldGuard atau memberikan bypass build umum.

Tunduk memblokir aktivasi sihir sendiri dan jalur interaksi/ritual/carry yang diintegrasikan dalam source ini. Plugin ability lain yang tidak memiliki adapter terverifikasi belum dapat diklaim terblokir seluruhnya. Animasi kamera Telekinesis memakai API hurt-animation tanpa damage; hasilnya terbatas pada animasi vanilla, bukan kontrol bebas kamera. Kepadatan partikel bergantung pengaturan client. Pelepasan tidak menambahkan Slow Falling atau perlindungan jatuh. `/me` dan `/do` kini memakai display paket tanpa spawn entity world, satu anchor penumpang client dan clearance terkonfigurasi; penumpang carry sebenarnya dipertahankan. Kelancaran visual belum diuji dengan client.

Pengujian otomatis membuktikan logika yang diuji, bukan seluruh perilaku Bukkit. Sebelum live, uji setidaknya:

- Migrasi salinan data produksi, konflik file, restart dua kali, dan kelanjutan migrasi terputus tanpa mengubah saldo/progres.
- Startup tanpa PAPI, dengan PAPI, reload PAPI, keempat placeholder dua pemain, pecahan, dan refresh TAB.
- Carry mulai/selesai serta `/me`/`/do` sambil berjalan, teleport, mati, dan membawa penumpang.
- NPC klik kiri/kanan, editor dua admin, custom potion/book/item, template, copy/delete/create ulang ID, jumlah maksimal, harga berubah, inventory penuh, item/saldo kurang, spam klik.
- Putus paksa server pada setiap fase transaksi; cocokkan receipt ledger, native playerdata, journal, audit. Karantina tidak boleh dilewati dengan menghapus receipt.
- Kepemilikan offline, duplicate/ke-10, spam command/GUI, reset cooldown saat aktif, relog/restart.
- Bola domain tertutup atas/bawah, 20 detik pembentukan, 300 detik aktif, 20 detik pemulihan; keluar/masuk, grup LP diwariskan, healing/damage/debuff, container custom NBT, hopper, ledakan/piston dan proteksi region.
- Restart/mati/logout pemilik domain pada tiap fase, crash tengah pemulihan, world belum dimuat; korban keluar tidak menghentikan penggunaan pemilik.
- Telekinesis plafon, mount/carry, ender pearl/chorus/teleport lain, serangan tetap diperbolehkan, suara berkala, dan fall damage alami setelah dilepas.
- Tunduk crawl paksa pada region terproteksi, korban masih menoleh, upaya keluar crawl, GSit lain, mati/logout korban dan pemilik, serta efek potion sah dari sumber lain.

Tidak ada pengujian langsung server/client Minecraft yang dilakukan dalam sesi implementasi ini. Hasil build dan hitungan pengujian final dicatat terpisah pada `BUILD-VERIFICATION-2026-10-25.md`.
